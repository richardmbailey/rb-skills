# RB Build Test Suite

This is the instructions-and-references edition requested first. Invoke
`$rb-build-test-suite` in Codex or `/rb-build-test-suite` in Claude Code to construct
or extend a project's testing workflow using its own tools. One invocation handles
building, independent auditing, authorized repairs and final verification. The host
calls the auditor and manages each cycle; you do not need to alternate skills.

The default project workflow reuses existing test commands and native reports,
with one evidence note and a simple HTML summary. It covers all 43 capabilities
at adoption while concentrating new code on substantive tests. Independent
scientific checks, change-impact review, final identity checks and failure
preservation remain required where applicable.

The full module/evidence/report contracts apply to the assurance workflow when
requested, already adopted or needed for a new enforced acceptance boundary.
The skill supplies no executable runner, adapters or renderer. Generated tools
need their own tests; ordinary projects need not construct the general system.

Start with [SKILL.md](SKILL.md). The schemas are reference contracts, not proof
that a record is true or that a suite ran. The behavioural eval manifest defines
future trials; validation of its format is not a completed agent evaluation.

Every build or extension automatically follows the
[paired audit workflow](../rb-audit-test-suite/references/paired-workflow.md).
The builder writes deterministic tests; a separate auditor writes executable
challenges. The auditor skill supplies a narrow local command/state coordinator,
not the deferred full assurance runner. Existing project tools and native reports
remain the default. Acceptance requires the declared checks and current review;
agent agreement alone does not establish test coverage.

The default limit is three assessment rounds, including the first. If delegation
is unavailable, a required decision or authority is missing, or the limit is
exhausted, the agent reports incomplete acceptance and the blocker. An explicit
request for planning-only or no audit narrows the deliverable; it is not full
verification. Routine execution of an adopted suite still uses its saved command.
