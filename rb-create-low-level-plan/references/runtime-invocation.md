# Shared Runtime Invocation

The runtime is owned by `rb-safe-operation`; do not import sibling source or install dependencies.

Use only the canonical `${CODEX_HOME:-~/.codex}/rb-safe-operation/current.json` control manifest. Ignore `RB_SAFE_OPERATION_MANIFEST` and `RB_SAFE_OPERATION_CONTROL_ROOT`; they are not trust inputs. Read only enough to obtain `launcher_bootstrap_interpreter_path`, then invoke that absolute interpreter as `<launcher_bootstrap-interpreter> -I -S -B ${CODEX_HOME:-~/.codex}/skills/rb-safe-operation/scripts/run_runtime.py <CLI command>`. The launcher has no control-root override; disposable tests select an isolated canonical root through `CODEX_HOME` before explicit setup. It validates bootstrap flags and identity, its own path and hash, the manifest-pinned source and lock, the complete installed environment, interpreter, and installed package before dispatch. Never invoke `interpreter_path` or `cli_module` directly. Require runtime `0.3.0`, public plan/run schema `3.0`, `pydantic==2.13.4`, and `pydantic-ai-slim==2.19.0`. A missing, stale, or incompatible manifest stops with the named packaging diagnostic.

Planning and assessment also require explicit canonical `ProviderGrant` and root `RunResourceGrant` artifacts. Generate the capability profile with `host-capabilities --adapter json_line` for the reviewed Codex CLI route, or `--adapter pydantic_ai` only for the separately selected compatibility route, and pass it unchanged. Codex planning must bind the closed `codex-cli` provider profile and `CODEX_CHATGPT_LOGIN` handle; it must not discover an API key, alternate executable, provider, or model.
