What the audit demonstrated

Healthy copies passed. Faulty copies failed the intended assertions for sequential updates, a missing final step, wrong speed, wrong sign, broken periodic wrapping, missing stability validation, accepted NaN, wrong distance units, wrong exported time and suppressed CLI errors.

The audit also ran six coordinator scenarios and seven receipt controls. Four independent science checks used requirements-derived references. Fourteen additional tests qualified the reused evidence parser. No selected fault survived.

The loop caught a workflow defect

Round 1 passed the numerical checks but failed lint because the working directory changed how Ruff classified the model import. The builder made that classification explicit without changing numerical code, tests or scientific criteria. Round 2 reran every required command, then remained pending until the separate auditor approved it. Earlier invalid audit adapter experiments are preserved and described in the evidence note.

What this does and does not establish

These results verify the stated bounded implementation and selected faults on Python 3.14.2/macOS ARM64. They do not establish empirical material behaviour, exhaustive correctness or a universal defect-detection rate. Both agents used separate contexts but shared a model family and filesystem.

Coverage measured 47 of 53 statements and 15 of 16 branches: the native combined display is 90%. Missing coverage is confined to the CLI entry/body, which real subprocess tests exercise separately. Strict typing covers the model; lint and formatting cover all four example Python files. Hosted CI and other environments were not run.
