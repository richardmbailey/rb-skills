# Shared Runtime Invocation

The runtime is owned by `rb-safe-operation`; do not import sibling source or install dependencies.

Use only the canonical `${CODEX_HOME:-$HOME/.codex}/rb-safe-operation/current.json` control manifest. Ignore `RB_SAFE_OPERATION_MANIFEST` and `RB_SAFE_OPERATION_CONTROL_ROOT`; they are not trust inputs. Read only enough to obtain `launcher_bootstrap_interpreter_path`. Resolve `<installed-rb-safe-operation-skill>` from the selected skill's actual directory, then invoke the absolute interpreter as `<launcher-bootstrap-interpreter> -I -S -B <installed-rb-safe-operation-skill>/scripts/run_runtime.py <CLI command>`. The launcher has no control-root override; disposable tests select an isolated canonical root through `CODEX_HOME` before explicit setup. It validates bootstrap flags and identity, its own path and hash, the manifest-pinned source and lock, the complete installed environment, interpreter, and installed package before dispatch. Never invoke `interpreter_path` or `cli_module` directly. Require runtime `0.3.0`, public plan/run schema `3.0`, `pydantic==2.13.4`, and `pydantic-ai-slim==2.19.0`. A missing, stale, or incompatible manifest returns a false assessment with the named packaging diagnostic.

Assessment requires explicit canonical `ProviderGrant` and root `RunResourceGrant` inputs and the exact capability profile emitted by `host-capabilities --adapter <adapter>`. The reviewed Codex CLI route uses `json_line` plus the closed `codex-cli` provider grant and `CODEX_CHATGPT_LOGIN` handle. Pass all three inputs unchanged to preflight and assessment. Never infer an API key, executable, provider, model, or broader authority from environment variables or conversation.
